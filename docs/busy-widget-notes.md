# The busy widget: how Plasma uses its art (spike for N-404, 2026-11-15)

Verified by reading the splash QML in the Fedora packages in the build VM (`plasma-lookandfeel-fedora` for the three
Fedora look-and-feels, `plasma-workspace` for Breeze). Nothing here is assumed.

## What the splash does with `busywidget.svgz`

Fedora's and Breeze's `contents/splash/Splash.qml` all have the same block:

- `Image { source: "images/busywidget.svgz"; sourceSize 2 grid units wide and high }`, about 36 px at 1x scaling.
- `RotationAnimator on rotation { from: 0; to: 360; duration: 2000; loops: Animation.Infinite; running: Kirigami.Units.longDuration > 1 }`.
  The duration is fixed on purpose (not scaled by the user's animation speed); it does not run at all when animations
  are switched off.
- It is faded out when the splash reaches stage 5, and sits in the middle of the space below the logo (`plasma.svgz`).

So the animation is NOT in the file. The art is ONE static picture that is turned about its centre. It has to look right
while it turns and be centered on its view box. If the logo were inside the file, the logo would spin too, so the file
that replaces `busywidget.svgz` is the comet ring only; the logo is the separate `plasma.svgz` image above it.

## Where the art is used

Only the post-login splash. The four files in the brand art submission are the same mechanism:
`org.fedoraproject.fedora`, `fedoradark`, `fedoralight` and `org.kde.breeze` (`.desktop/contents/splash/images/busywidget.svgz`).
The lock screen and the login screen do not use this file (they use Plasma's own BusyIndicator component, a different job).

## Constraints for the art

- Qt draws it with an `Image` (QtSvg), not Plasma's themed SVG loader: plain shapes and plain fills. Fedora's own file
  uses `.ColorScheme-*` style classes; ours does not need them. No masks, gradients, filters or opacity (tested).
- The view box is 136 by 136 in Fedora's file; ours keeps that so it drops in. The orbit is centered on the box.
- It is shown small (36 px, 72 px at 2x), so the tail and the gap are drawn thick enough to survive that.

## What N-404 ships (`assets/art/comet/`)

`busywidget.svgz` (the Paper comet, drop-in), `svg/nisse-comet*.svg` (Paper, ink, black, white, symbolic), the preview
frame with the n, `sheet.png`. Generated by `tools/art/comet.py`. Checked by `tools/art/tests/test_comet.py` and, in the
build VM, `tests/e2e/test_comet_qt.sh` (`tests/qml/tst_comet.qml`: Qt loads the svg and the svgz, draws a comet, turns it
clockwise by the angle it is told to, a full turn comes back, and the same RotationAnimator the splash uses turns it).
